# 대형 파일 해시 확인과 취소

2026-10-03에 `file_hash(path, cancel=None)`을 보강했다. 열기 전, 각 1MiB 읽기 전후,
최종 반환 전에 취소를 검사한다. 취소 시 파일은 닫히며 불완전한 digest를 반환하지 않는다.
기존 호출의 SHA-256 결과와 선택적 인자 호환성은 유지한다.

분석 시작, backend 인덱싱 및 bridge 캐시 키, GUI live 원본 확인, backend live 요청에
작업의 Cancellation을 전달한다. 이미 취소된 요청은 파일을 열지 않으며 backend live
해시 확인에서 취소되면 기존 fingerprint를 바꾸거나 JEB 요청을 보내지 않는다.

## 로컬 측정

`python tools/benchmark_hashing.py`로 별도 임시 128MiB 합성 파일을 생성했다.
단일/연속 두 번 해싱을 각각 3회, 취소를 5회 측정했다. 사용자 APK는 읽거나 변경하지 않았다.
파일은 측정 후 삭제하고 JSON 결과는 보존했다.

- 단일 해싱 중앙값: 122.47ms
- 연속 두 번 해싱 중앙값: 243.46ms
- 취소 요청이 실제 실행된 뒤 반환까지: 0.16~0.62ms, 5회 모두 취소
- 5ms 타이머의 실제 요청 시점: 시작 후 10.03~15.02ms

결과 파일: `C:\validation-temp\aoseye-hash-kw5_w4c0\hashing.json`.
생성 직후 같은 파일을 읽은 로컬 캐시 조건이며 실제 대형 APK 분석 시간이나 cold disk,
네트워크 드라이브, Qt 이벤트 처리 지연을 나타내지 않는다. 측정치는 응답시간 보장이 아니다.
동기 OS read 자체는 중단할 수 없으므로 느린 저장소에서는 한 번의 read가 끝날 때까지
취소 확인이 지연될 수 있다.

## 중복 읽기 판단

GUI 원본 확인과 backend 요청 확인이 모두 수행되는 경로는 여전히 파일을 두 번 읽는다.
GUI 검사는 저장된 AST/소스 캐시가 반환되는 경우에도 원본 변경을 차단하고, backend 검사는
CLI 등 GUI를 통하지 않는 호출을 보호한다. 단순히 하나를 없애면 보호 범위가 달라진다.
이번에는 취소 응답을 개선하고 비용을 측정했으며 중복 해싱 최적화를 완료하지 않았다.
mtime/크기만으로 해시를 재사용하지 않는다. 요청 범위 내 검증 결과 재사용을 도입하려면
캐시 반환·직접 backend 호출·파일 교체 및 늦은 취소를 함께 검증해야 한다.

회귀 검사는 선행 취소, 빈/작은/청크 경계 파일의 digest 일치, 읽기 도중 취소 후
파일 닫기와 추가 읽기 차단, backend fingerprint 보존 및 미전송을 포함한다.
기존 GUI 원본 보호 9개와 함께 선택 실행한 15개 테스트도 통과했다.
최종 전체 실행은 실제 JEB 통합 5개를 포함해 **373 passed (44.62초)**였다.
wheel 빌드 성공, SHA-256:
`89ed811e1481d4f9e8dc3862542f85cf56ed732611c6f46a238499aa8ba89b12`.
이번 wheel의 별도 가상환경 설치 검증은 다시 수행하지 않았다.

## 후속: live 요청의 단일 해시 검증 (2026-10-03)

위의 이중 검사 상태를 보강했다. GUI는 저장된 program/원본 경로/기대 SHA-256을
backend에 전달하고, 공개 live 함수 `get_ast`, `get_decompiled_source`, `get_jeb_xrefs`가
호출마다 원본을 한 번 검증한다. 검증 결과는 해당 호출의 JEB 요청 인자로만 전달한다.
공유 검증 토큰, 시간 기반 digest 캐시, mtime/크기 기반 생략은 도입하지 않았다.

AST/소스가 메모리에 있어도 검증을 먼저 수행한다. 따라서 GUI를 거치지 않는 직접
backend 캐시 조회도 원본 누락·변경·취소를 차단한다. 오프라인 저장 근거 열람은 기존
GUI의 저장 모델 표시 경로로 제공하며, live API와 구분한다. 다음 호출에서는 다시
해싱한다. 분석 시작의 application/backend 두 단계 해싱은 이번 최적화 범위가 아니다.

12개 회귀를 추가했다: 3종 직접 호출/다음 호출의 해싱 횟수, 캐시된 AST·소스의
누락/변경/취소 차단과 복구, 실제 GUI controller의 3종 요청당 한 번 읽기.
기존 원본 보호 9개와 함께 21개가 통과했다. 조회 함수 전체를 대체하는 GUI 테스트
double에도 원본 검증 계약을 명시적으로 적용했다.

128MiB 합성 파일을 새로 측정했다. 단일/이중 해싱 중앙값은 142.90/259.84ms,
실제 Python backend AST 경로의 중앙값은 비캐시 137.12ms, 캐시 130.97ms였다.
backend 응답은 mock이며 JVM·디컴파일 시간을 포함하지 않는다. 각 3회 로컬 캐시
측정으로, 실제 APK 전체 분석 성능 향상을 증명하지 않는다. 취소는 5회 모두 성공했고
실제 요청 후 반환은 0.33~0.65ms였다. 임시 합성 파일은 제거하고 결과를 보존했다:
`C:\validation-temp\aoseye-hash-2tkz3gyt\hashing.json`.

이전처럼 검증과 JEB 파일 읽기 사이 외부 변경을 원자적으로 막지는 않는다.
파일 스냅샷/잠금이 없는 한 해당 경쟁 상태는 남는다.
새 wheel SHA-256:
`552861bc1f14c8c19bc71e90fe94c82037cc2bda3ba4ccb6f57f0ac7ecfc4c15`.
최종 전체 회귀: 실제 JEB 통합 5개 포함 **385 passed (44.28초)**.
wheel 빌드를 확인했으며 이번 버전의 별도 가상환경 설치 검증은 반복하지 않았다.
