# GUI 인덱스 정책 선택 및 저장 근거 표시

JEB settings → Index collection policy에서 native/manifest-first를 선택하고
Save index policy를 누른다. 저장 전 선택은 초안이며 창을 다시 열면 저장값으로 복원한다.
설정은 새 분석에만 적용된다. 저장된 결과·메모·현재 근거 화면과 기존 결과의 정책은
변경하지 않는다. 저장 성공 시 GUI/application/backend 설정을 함께 갱신하며 JEB를
호출하지 않는다. 작업 중 변경, 잘못된 값, 설정 파일 쓰기 실패는 반영하지 않는다.

상단 범위 배너는 결과의 provenance에서 요청 정책, program capabilities에서 유효
정책을 읽는다. manifest-first 요청 후 native 폴백도 별도로 표시한다. 구형 결과나
인식되지 않는 값은 unknown (not recorded)로 표시하며 현재 설정으로 추정하지 않는다.
정책 표시는 저장/재열기 후에도 유지된다. 구형 unit 내부/신규 unit 간 전역 정책을
구분하며 소유권이나 실행 가능한 진입점의 증거가 아니라는 안내를 표시한다.

700px 높이 창에서는 설정 내용이 세로 스크롤된다. 하단 선택/저장 버튼까지 접근 가능한
QML 렌더링을 확인했다. 검증 이미지: `build/gui-index-policy.png`.
신규 10개 테스트는 정책/폴백/구형 표시, 설정 저장·재열기·기존 결과 보존,
유효성/작업 중/쓰기 실패 원자성, QML 버튼 연결·비활성·스크롤을 검사한다.
사용자 설정이나 원본 APK는 수정하지 않았고 이번 단계에서 대형 APK 재분석은 하지 않았다.

전체 회귀 **655 passed (94.78초)**, 실제 JEB 통합 15개 포함. 스크롤 높이 명시 후
신규 GUI 테스트 10개도 별도로 재통과했다. wheel 재빌드 완료, SHA-256:
`859ceb4e3e51941a90251ad4431353684c5439f5910e69703a89b154f9cf579c`.
