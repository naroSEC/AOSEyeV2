# GUI 단일 호출 대상 후보 미리보기

사용 순서:

1. Diagnostics → Call sites에서 `indexed_body_missing` 등 분류를 조회한다.
2. Caller 링크로 실제 저장 호출 명령의 Bytecode 화면으로 이동한다.
3. Candidate limit (KiB)를 지정하고 Preview target (JEB)을 누른다.
4. 성공하면 독립 읽기 전용 창에서 대상 본문 DTO와 출처/예산 정보를 확인한다.

기본 제한 256KiB, 범위 1~1024KiB다. 기존 단일 static/direct 후보 API의 사전 조건을
그대로 적용한다. known unit/code 선언이 없는 unindexed_target 등은 거부된다.
JEB와 원본 APK/DEX가 필요하고 원본 지문을 검사한다. 모호/변경된 대상은 추측하지 않는다.
바이트 한도는 반환 후보에 대한 계수이며 정규화 순간 JVM 메모리 제한이 아니다.

미리보기는 독립 창의 일시적 문자열로만 보관한다. Program/Findings/메모/provenance/
complete와 호출자 화면/위치를 바꾸지 않으며 프로젝트 저장 대상에도 포함하지 않는다.
창을 닫으면 메모리 후보를 폐기한다. 후속으로 별도 후보 내보내기를 추가했다
(`CANDIDATE_EXPORT.md`). 분석 병합/재분석은 아직 없다.
후보 조회에 따른 JEB 내부 처리/임시 IPC는 발생하지만 원본 APK는 수정하지 않는다.

조회는 worker에서 실행한다. 예산 초과는 본문 없이 상태만 표시하고 창을 열지 않는다.
오류/취소/완료 직전 취소는 기존 근거 화면을 보존한다. 결과 객체·호출 위치·섹션·탭이
바뀐 뒤 도착한 후보는 거부한다. 조회 중 UI의 중복 요청은 차단한다.
원문은 PlainText로 표시하며 HTML/코드를 실행하지 않는다.

## 검증

신규 8개: 성공/예산/오류/취소/늦은 취소의 저장 결과·화면 보존, 잘못된 예산,
오래된 응답 거부, 실제 QML 버튼/독립 창/닫기 폐기, 실제 JEB GUI worker 왕복.
JEB fixture의 대상 본문을 메모리에서 제거한 뒤 후보를 조회했고, 기존 결과에
본문이 다시 추가되지 않음을 확인했다. 사용자 실제 프로젝트/설정은 수정하지 않았다.
QML 검증 화면은 `build/gui-call-candidate.png`이며 합성 후보의 레이아웃 확인용이다.
실제 JEB 동작은 별도 통합 테스트로 검증했다. 대형 APK 재분석은 하지 않았다.
전체 회귀 **708 passed (130.62초)**, 실제 JEB 통합 17개 포함.
wheel 재빌드 SHA-256:
`14ad4d5a4aa7750110330b73a101a6d7cde3020dded9abb6c5ee9b3d569c1944`.
독립 가상환경 설치 검증은 이번 단계에서 반복하지 않았다.

독립 내보내기/출처 보존과 검증 계약을 후속 구현했다. 후보를 원래 분석에
반영하려면 별도의 병합 충돌·분석 예산·finding 재평가·취소 정책을 먼저 마련해야 한다.
