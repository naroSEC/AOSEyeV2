# 저장 호출 대상 위치 탐색

Diagnostics에서 분류를 선택하고 Call sites를 누르면 저장 본문으로 목록을 조회한다.
기본 UNAVAILABLE은 body_available을 제외한다. 각 분류와 ALL 필터를 제공하며
GUI 페이지는 100개, API는 최대 300개다. Previous/Next는 현재 표시된 페이지의
필터를 사용한다. 드롭다운 변경은 Call sites를 누르기 전까지 적용되지 않는다.

행에는 호출자·unit·DEX 오프셋·opcode·원시 대상·분류가 있다. 링크는 **호출자**로만
이동한다. 대상 본문을 자동 조회/추가하거나 같은 이름의 다른 unit 본문으로 대체하지 않는다.
호출자 unit 미기록, 음수/잘못된 오프셋, 중복 오프셋은 링크하지 않는다.
실제 위치 이동은 기존 bytecode_location의 unit/오프셋 검증을 거친다.

분류는 집계와 같은 코드에서 생성한다. 목록은 페이지 크기만 보관하며 필터별 총 수를
구하기 위해 저장된 선언/명령을 끝까지 읽는다. 추가 메모리는 선언/출처, 한 호출자의
오프셋 빈도, 페이지 크기에 비례한다. 256개 단위 취소 검사를 유지한다.
작업 스레드에서 조회하고 취소·실패 시 기존 화면/페이지를 보존한다. 결과 객체가 바뀌거나
Diagnostics에서 벗어난 뒤 도착한 응답, 완료 직전 취소는 반영하지 않는다.

구형 프로젝트도 저장 본문에서 조회할 수 있으나 원래 provenance/통계를 수정하지 않는다.
따라서 상단 not recorded와 현재 조회 결과가 함께 보일 수 있다. 이는 과거 저장 통계와
지금 재계산한 목록을 구분하기 위한 동작이다. findings, 메모, complete 값은 바꾸지 않는다.
표시 총 수는 저장 데이터의 필터 일치 수이며 APK 전체 호출 수가 아니다.

## 검증

신규 9개 테스트: 305개 호출의 첫/끝/빈 페이지, 분류 합계 일치, 출처 불명/중복 오프셋
비링크, 입력 검증, 취소, GUI 위치 이동, 오류/늦은 취소 시 페이지 보존, 오래된 응답 거부.
실제 QML 버튼 연결과 렌더링을 확인했다: `build/gui-call-targets.png`.
전체 회귀 **683 passed (121.89초)**, 실제 JEB 통합 15개 포함. QML 연결 검사를
보강한 신규 9개도 별도로 재통과했다. wheel 재빌드 SHA-256:
`7e30d516f66590bfecedcdbe839c5c8c70035b528b70ddac339e84aa9965e334`.
독립 가상환경 설치 검증은 이번 단계에서 반복하지 않았다.

기존 amoremall 부분 프로젝트를 읽기 전용으로 조회했다. UNAVAILABLE 총 7,937개,
offset 7,900의 마지막 37개 모두 bytecode_location으로 호출자 위치를 확인했다.
조회/링크 확인 약 0.037초는 단일 관측값이며 성능 보장이 아니다.
JEB 재분석, APK 실행, 사용자 설정/기존 프로젝트 수정은 하지 않았다.

## 제한적 확장 설계 — 아직 구현하지 않음

자동 확장 전에 indexed_body_missing과 unindexed_target을 분리해야 한다. 후자는
플랫폼/외부 API나 상속 대상일 수 있어 앱 코드 누락으로 확정하지 않는다.
첫 구현 후보는 명시적 요청, 별도 작은 본문/바이트 예산, 깊이 1, 확정된 unit의 직접
호출 대상이다. 기존 선택 항목을 밀어내지 않고 별도 결과로 저장하는 방식이 필요하다.
같은 대상 중복/순환은 방문 집합으로 차단하고 가상/인터페이스/불명 unit은 자동 확장하지
않는다. 원본 해시 확인·취소·부분 실패 시 기존 근거 보존도 필수다.
후속으로 단일 직접 호출 대상 조회 및 후보 예산 계약을 검증했다(`CALL_TARGET_CANDIDATE.md`).
GUI 후보 미리보기와 실제 결과 병합/재분석은 아직 구현하지 않았다.
