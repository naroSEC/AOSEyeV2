# 메서드 내보내기 바이트 예산 (2026-10-04)

`Settings.max_export_mib`는 기본 64MiB, 허용 범위 1~256MiB인 정수다.
`aoseye analyze <apk> -o <report> --max-export-mib 8` 또는 설정 JSON으로 지정한다.
전용 GUI 입력란은 아직 없지만 GUI 분석도 저장 설정을 사용한다. 기존 설정 JSON에는
기본값이 적용되며 큰 APK는 이전과 달리 기본 바이트 예산에서 부분 분석될 수 있다.

Jython/CPython 공용 `ExportBudget.py`가 ASCII 이스케이프 JSONL의 개행을 포함한
바이트 수를 계산한다. 한도를 초과하는 첫 레코드는 쓰지 않고 이후 본문 정규화도
생략한다. 한도에 정확히 맞는 레코드는 허용한다. 이미 쓴 JSONL은 완전한 줄을 유지하며
작은 후속 메서드만 골라 채우지 않는다. 선언 목록은 계속 수집한다. 누락 개수는
선언된 코드 본문 항목 수이며 고유 메서드 시그니처 수와 다를 수 있다.

후속 선언 인덱스 예산 도입으로 선언 목록도 별도 한도 안에서만 수집한다.
본문 누락 수는 그 선언 범위 안에서 집계되며, 선언 범위 밖 제외 수는 별도 진단에 기록한다.
현재 기준은 `DECLARATION_INDEX_BUDGET.md`를 함께 참고한다.

정상 bridge 응답에는 사용 바이트/한도/제외 본문 수와 부분 분석 진단이 포함된다.
애플리케이션은 진단이 있으면 complete=false를 유지한다. Python 수신부도 파일 크기와
읽은 바이트 합계를 검사한다. 예산과 helper 소스 해시를 캐시 키에 포함해 더 큰 예산의
캐시가 작은 예산에 재사용되지 않도록 했다. 분석 provenance에 설정값을 남긴다.

이 제한은 **메서드 JSONL 파일에만 적용**한다. JEB 내부 상태, 선언 인덱스, 단일 메서드
정규화/직렬화의 순간 메모리, Python 최종 모델, 최종 프로젝트 크기를 제한하지 않는다.
JVM이 정상 응답을 보내기 전에 죽으면 임시 스트림을 성공 결과로 복구하지 않는다.
부분 응답 수신 전에 중단되면 이미 쓴 본문도 보존되지 않을 수 있다.

설정 범위/구형 설정, 캐시 키 변경, 초과 응답 거부 및 기존 program 보존.

byte 예산만으로 JVM 메모리 문제가 해결됐다고 주장하지 않는다.
