# 단일 직접 호출 대상 본문 후보 조회

내부 backend API `preview_call_target(caller, offset, cancel, max_bytes=262144)`를 추가했다.
GUI 독립 미리보기를 후속으로 연결했다(`GUI_CALL_CANDIDATE.md`). 자동 확장/저장 결과
병합은 아직 연결하지 않았다. 호출 한 번에 대상 하나만
조회하며 깊이 확장이나 후보의 호출을 재귀 탐색하지 않는다.

사전 조건은 저장된 호출자 unit과 고유한 비음수 오프셋, invoke-static/direct
(각 range 포함), 아직 본문이 없는 대상, 코드 존재가 기록된 정확한 선언 및 단일
알려진 대상 unit이다. virtual/interface/custom/polymorphic/super, unit 불명/모호,
인덱스 밖 대상, 이미 저장된 본문은 거부한다. 저장된 원본 지문이 없으면 거부하며
원본 APK/DEX SHA-256도 확인한다.
선언/명령 순회는 256개마다 취소를 검사한다.

JEB는 모든 unit에서 해당 시그니처의 실제 정의를 조회한다. 요청 unit이 있어도 다른
unit의 중복 정의를 먼저 제외하지 않는다. 정의가 정확히 하나이고 unit이 일치하며
코드가 있어야 정규화한다. 저장 인덱스에서 제외된 중복 정의도 이 단계에서 거부할 수 있다.

예산은 기본 256KiB, 허용 1바이트~1MiB의 ASCII JSON+개행 계수이며 메서드 후보 DTO에
적용한다. 초과하면 BUDGET_EXCEEDED만 반환하고 본문은 반환하지 않는다. 전체 응답
envelope/JEB artifact/정규화 중간 객체/RSS 제한은 아니다. 특히 정규화 후 계수하므로
하나의 큰 메서드 처리 순간 메모리는 이 한도로 제한되지 않는다.

Python은 DTO 스키마, 대상 시그니처, unit, 요청 예산, 계수 바이트를 재검증한다.
Jython 문자열 전달 표현과 Python 표현의 크기가 다르면 보수적으로 거부한다.
성공 결과는 별도 후보 dict와 원본 해시·호출자·오프셋이며 기존 Program/Findings/
메모/provenance를 변경하지 않는다. 조회에 따른 JEB 내부 처리와 임시 IPC는 발생한다.
반환 직전 취소도 반영하지 않는다. 호출자 원본 결과의 재분석을 수행한 것은 아니다.

## 검증 범위

신규 17개: 사전 조건/원본 변경/예산, 응답 출처·바이트 불일치/늦은 취소,
저장 program 불변, bridge 전체 unit 중복/출처/코드/예산 거부.
실제 JEB fixture를 인덱싱한 후 대상 본문 하나만 메모리에서 제거해 누락을 만들고,
1바이트 예산 거부와 정상 예산 후보 조회를 확인했다. 반환 시그니처/unit은 제거 전과
일치하며 저장 program에는 다시 넣지 않았다.
이는 대형 메서드/대용량 앱 메모리 검증이나 모든 호출 종류 지원의 검증이 아니다.
사용자 APK와 기존 저장 프로젝트/사용자 설정은 변경하지 않았다.
전체 회귀 **700 passed (135.47초)**, 실제 JEB 통합 16개 포함. 지문 누락 거부 보강 후
신규 17개도 별도로 재통과했다. wheel 재빌드 SHA-256:
`4de414df481a755b33de7240c29e35bdf3f7d53a211e6107fda2fa040bae735b`.
독립 가상환경 설치 검증은 이번 단계에서 반복하지 않았다.

GUI 후보 조회와 독립 미리보기, 오류/취소 시 기존 근거 보존은 후속 구현했다.
후보를 실제 분석에 반영하려면 별도 병합/재분석/출처 정책이 필요하다.
