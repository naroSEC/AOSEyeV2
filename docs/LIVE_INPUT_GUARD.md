# 원본 APK/DEX 변경 시 live 조회 보호

## 동작

AST·JEB XREF·디컴파일 요청은 원본 경로와 저장된 SHA-256을 확인한다. 파일이 없거나
내용이 다르면 요청을 차단하고 재분석이 필요하다는 stage 메시지를 표시한다.
이 검사는 기존에 있었으나 오류 시 근거 화면이 덮어써지는 문제가 있어 보강했다.

live 요청 실패 또는 취소 시 이전 탭, 근거 내용, 참조 목록, 필드/JEB XREF 페이지,
Review 요약을 복원한다. 분석 결과·Finding 선택·위치·탐색 이력·메모는 변경하지 않는다.
늦은 성공 응답도 취소가 요청됐다면 반영하지 않는다. 정상 성공 시에만 새 근거를 표시한다.
backend 자체의 캐시/원본 해시 검사도 유지하며 검증을 우회하지 않는다.

파일이 없어도 저장된 DEX 기반 Bytecode/CFG/참조와 메모는 열람할 수 있다.
프로젝트 저장/재열기도 가능하다. 원본 바이트를 복구하면 live 조회를 다시 시도할 수 있다.
다른 버전의 APK를 사용하려면 새로 분석해야 한다. 원본 경로 자동 교체나 해시 갱신은 하지 않는다.

## 검증 범위 (2026-10-02)

- 회귀 9개: AST/JEB XREF/Code 각각에 대해 파일 누락·내용 변경·늦은 취소를 검사했다.
  원본 불일치 시 backend 조회 함수가 호출되지 않고 이전 화면/위치/메모가 유지되는지,
  저장된 Bytecode 열람 및 프로젝트 저장/재열기, 원본 복구 후 재시도를 확인했다.
- 실제 JEB/QML 통합: 분석 fixture의 결과를 유지한 채 임시 원본 경로를 누락/변경 상태로
  설정하고 3종 live 조회를 차단했다. fixture 원본 바이트를 임시 경로에 복구한 뒤
  실제 AST 조회에 성공했고 이후 XREF·디컴파일도 통과했다.
- 테스트는 임시 파일만 변경한다. 사용자 APK와 원래 fixture는 수정하지 않는다.
- 전체 회귀: 실제 JEB 통합 5개를 포함해 **367 passed (55.00초)**.
  wheel 빌드 성공, SHA-256:
  `e78b9a69932943c45386b4675fea757fd3c6ba74ecd570ecf600c7d88267a2b0`.
  이번 wheel의 새 가상환경 설치 검증은 별도로 실행하지 않았다.

```powershell
python -m pytest tests/test_live_input_guard.py -q

python -m pytest tests/test_gui.py::test_live_gui_jobs_share_backend -q
```

offscreen QML/controller 검증이며 수동 클릭 인수를 대체하지 않는다. 파일 해시 검사와
JEB의 파일 읽기 사이에 외부 프로세스가 파일을 바꾸는 경쟁 상태를 원자적으로 차단하는
스냅샷/잠금 기능은 아니다. 권한 ACL 오류, 대형 APK 해싱 지연, 장시간 파일 변경 감시는
이번 검증 범위 밖이다. 저장된 근거는 과거 분석 결과이며 현재 디스크 파일의 근거로
재해석하지 않아야 한다.
