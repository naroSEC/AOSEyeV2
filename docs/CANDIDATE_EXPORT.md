# 독립 후보 내보내기와 출처 보존

후보 미리보기의 Export separate candidate에서 **새 `.candidate.json` 파일**로 저장한다.
현재 프로젝트 저장과 다른 파일 형식이며 Program/Findings/메모/complete에는 병합하지 않는다.
프로젝트 Reopen으로 후보 파일을 열면 거부된다. 내부 `open_candidate`로 검증/재열기를
지원하며 GUI 후보 파일 재열기는 아직 연결하지 않았다.

조회 성공 시 후보를 deep copy하여 UTC 시각과 JEB 버전, 본문 SHA-256을 보관한다.
후보 payload에는 원본 입력 SHA-256, 호출자 시그니처/unit/오프셋/opcode, 대상 본문과
unit, 조회 예산/계수 크기가 들어간다. 이후 현재 설정이나 결과를 참고해 출처를 다시
만들지 않는다. 로컬 원본 파일 경로는 파일 형식에 추가하지 않았다.
창을 닫으면 메모리 후보를 폐기하지만 이미 내보낸 파일은 유지된다.

본문 해시는 정규화한 JSON의 무결성 확인용이다. 전자서명이나 신뢰된 원본 증명이 아니며
본문과 해시를 함께 고친 파일의 진위를 판단할 수 없다. 기록된 입력 해시/조회 시각/JEB
버전도 원본 APK와 대조하지 않고 진위가 확인된 것으로 취급하면 안 된다.

저장/읽기 양쪽에서 전용 kind/schema, 필수 키/미지 키, UTC 시각, 출처, Method 구조,
지원 opcode, 예산 및 실제 계수, 본문 해시를 검사한다. 후보 최대 1MiB, 별도 envelope
파일 최대 2MiB다. 편집/손상/불일치 후보는 실패 처리하고 프로젝트로 자동 변환하지 않는다.

완성한 임시 파일을 같은 디렉터리에 만들고 no-clobber hard link로 원자적으로 게시한다.
기존 파일은 절대 덮어쓰지 않는다. 이름 충돌이나 hard link 미지원 파일시스템에서는
실패하며 임시 파일을 정리한다. 다른 새 이름 또는 지원되는 로컬 파일시스템을 사용한다.
GUI 파일 선택기가 덮어쓰기 확인을 보여도 이 저장기는 기존 파일 덮어쓰기를 거부한다.
저장 오류는 미리보기 안에 표시하며 후보와 기존 분석을 유지한다.

## 검증

신규 10개 테스트로 전용 형식 왕복/프로젝트 로더 거부, 기존 파일 보존, 미완성 게시 실패
정리, 해시/예산/unit/원본 지문/schema/미지 키/시간 검증, GUI 실패 후 후보 보존·폐기를 검사했다.
기존 실제 JEB GUI 시험에 내보내기/검증 로더 왕복을 추가했고 실제 대상·입력 해시·호출자
unit 보존 및 원래 분석 불변을 확인했다. QML 내보내기 버튼 배치를 렌더링으로 확인했다.
사용자 실제 APK/저장 프로젝트/설정은 수정하지 않았다. 대형 APK 재분석은 하지 않았다.
전체 회귀 **718 passed (133.30초)**, 실제 JEB 통합 17개 포함.
wheel 재빌드 SHA-256:
`f2982b2cc5f9c46305d870b3095d5ce8fbd02559f95d73213a42adbf50a3a613`.
독립 가상환경 설치 검증은 이번 단계에서 반복하지 않았다.

다음 범위는 독립 후보 파일의 GUI 읽기 전용 재열기와 현재 프로젝트 출처 일치 여부 표시다.
본문 병합·추가 분석·finding 재평가는 여전히 별도 정책/검증이 필요하다.
