# 제한된 정수 상수 연산

add-int/lit8과 add-int/lit16을 지원한다. 부호 있는 32비트 정수 상수와 부호 있는 8/16비트
리터럴을 더하고 32비트 2의 보수 결과로 되돌린다. 음수 리터럴로 length-1 계산을 처리한다.
목적지의 이전 참조/상수/trace를 제거하고, 동일 원본/목적지 레지스터는 연산 전 값으로 읽는다.
원본 상수가 미확정이면 결과를 추정하지 않고 진단한다. 원본 입력 trace가 있다면 불확실성을
붙여 유지하며 상수만을 근거로 오염 흐름을 지우지 않는다. 잘못된 인자/리터럴은 진단한다.

DTO는 부호/0/리터럴 경계/32비트 오버플로, 동일 레지스터, defs 누락, 오래된 목적지 제거,
미확정 원본과 array-length 결과로 마지막 슬롯 선택을 검증한다.
실제 JDK/D8/JEB는 lastIndex(Object[]) 보조 메서드의 array-length→add-int/lit8(-1)을 확인한다.
계산한 인덱스로 Arrays.fill 입력 슬롯을 읽는 흐름과 기존 권한/Review/저장 왕복을 유지한다.
D8이 호출자 내 표현식을 sub-int/2addr로 바꾸는 경우가 있어 지원 명령을 별도 메서드로 검증했다.

분석 정책은 bounded-int-v3-multiply이다. 나눗셈,
비트 연산, long/float/double, 기호 연산 및 분기 판정은 이번 범위에 포함하지 않는다.
상수 해석이나 미검출은 실행 가능성/안전성 증명이 아니다.
명령 의미: [AOSP Dalvik bytecode](https://source.android.com/docs/core/runtime/dalvik-bytecode).

## 레지스터 덧셈·뺄셈

add-int/sub-int 및 각각의 /2addr 형식을 지원한다. 두 signed int 상수가 확인되면
연산 결과를 32비트로 되돌린다. /2addr의 첫 레지스터와 일반 형식의 겹친 목적지는 연산 전 값을 읽는다.
목적지의 이전 참조/상수/trace를 제거한다. 미확정/타입 또는 범위가 잘못된 원본은 진단하고
상수를 만들지 않는다. 입력 trace는 두 피연산자 중 외부 입력을 우선 선택해 불확실하게 유지한다.
전체 source 열거 또는 산술을 이용한 입력 검증 증명은 아니다.
DTO는 네 형식, 부호/0/경계 오버플로, defs 누락, 목적지 중복, 미확정/잘못된 인자,
대표 외부 trace 선택과 계산한 인덱스의 배열 읽기를 검증한다.
실제 JEB query의 arraySize(filled)-1에서 sub-int/2addr가 생성됨을 확인하고 마지막 슬롯의
입력 흐름을 검증한다(query 총 흐름 12개). 기존 리터럴 덧셈 검증도 유지한다.

## 정수 곱셈

mul-int, mul-int/2addr, mul-int/lit8, mul-int/lit16의 상수 곱셈을 지원한다.
음수/0과 32비트 오버플로를 처리하며 기존 레지스터·리터럴 연산의 목적지 정리 및
원본 미확정 진단/불확실한 입력 trace 보존 규칙을 공유한다. 미확정 값에 0을 곱한 경우도
상수로 단정하지 않는다. signed 8/16비트 리터럴 범위 밖 입력은 진단한다.
DTO는 네 형식, 부호/0/오버플로, 목적지 중복/defs 누락, 미확정 원본과 크기 계산 후
배열 할당·읽기를 검증한다. 실제 JEB tripleSize(Object[])의 mul-int/lit8(3)을 확인하고
반환값 3으로 배열을 할당해 마지막 슬롯의 입력 흐름을 검증한다. query 총 흐름은 12개다.
나눗셈/나머지/비트 연산과 long/float/double은 미지원이다.
